# Правила спорных результатов и сообщения

Пользователь согласовал предложенные сообщения как значения по умолчанию 23 октября 2026 года и поручил дать администратору выбор поведения.

Вкладка **Админка → Настройки → Спорные результаты и сообщения** задаёт общие правила для всех тестов:

- Равные максимальные баллы: смешанный профиль (по умолчанию) либо выбор среди лидеров по заданному приоритету четырёх измерений.
- Все измеренные показатели равны нулю: без ведущего измерения (по умолчанию) либо выбранное администратором направление. Отсутствующие измерения не считаются нулевыми; при отсутствии данных направление не назначается.
- Сообщения проверки оплаты, очереди/отправки/ошибки письма и отсутствия/смешения лидеров редактируются независимо на русском и английском. В смешанном профиле обязательна единственная метка `{dimensions}`; адрес в сообщениях о письме добавляется отдельно. HTML выполняться не может.
- Предпросмотр сразу показывает равные и нулевые баллы. Возврат значений по умолчанию изменяет черновик; требуется отдельное сохранение. При ошибке сохранения черновик остаётся в форме; при ошибке загрузки сохранение заблокировано.

Правила меняют выбор отображаемого профиля и архетипа; ответы, баллы, цены и исходные авторские описания не пересчитываются и не переписываются. Сайт и письмо используют одну реализацию выбора. При недоступных/некорректных правилах сайт показывает повторную загрузку профиля, а новый почтовый запрос повторяется позднее. Отсутствующая настройка означает согласованные значения по умолчанию.

Открытый результат использует текущие правила. Письмо фиксирует правила и авторское содержимое перед первым запросом к почтовому сервису: последующие повторы используют тот же текст и ключ идемпотентности. Изменение правил не переписывает уже подготовленные/отправленные письма. Старые письма могут отличаться от текущего представления сайта после изменения правил; это явно поясняется в админке.

## Хранение и выпуск

Один атомарно сохраняемый JSON-набор в `app_settings.result_presentation`; публично читается только этот дополнительный ключ, изменение защищено существующей ролью администратора. Ограничение размера — 64 КиБ; поля сообщений — до 1000 символов. Некорректный JSON/версия/перестановка/шаблон не принимаются интерфейсом и почтовым обработчиком.

Подготовленный патч `supabase/migrations/20261023073000_result_presentation.sql` ещё не применён к production. Он добавляет настройку со смешанным профилем и отсутствием лидера для нулей, сохраняет существующую настройку при наличии, переносит существующие RU/EN формулировки успешной отправки из `home_content` в новый набор (старые строки остаются), расширяет публичное чтение только на новый ключ и разрешает почтовому service_role чтение архетипов. Вопросы, результаты, платежи, файлы и исходные тексты не удаляются и не меняются.

Порядок выпуска: отдельно одобренный SQL-патч в IQ Tests (`afsoyuczexiztsjntkvi`), соответствующие серверные функции, затем согласованный выпуск сайта. Одобрение формулировок не является одобрением production SQL, платежных функций или публикации всего аудита.
